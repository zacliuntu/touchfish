# 故障排除

[English](TROUBLESHOOTING.md) · [返回说明](../README.zh-CN.md)

## 提示必须使用 X11

运行 `echo "$XDG_SESSION_TYPE"`。如果不是 `x11`，请注销，并在登录界面齿轮菜单选择“Ubuntu on Xorg”。远程桌面或嵌套会话也必须提供有效的 `DISPLAY`。

## 快捷键没有反应

- 从托盘打开设置，重新保存快捷键；若已被其他程序占用，TouchFish 会报告冲突。
- Ubuntu 可在系统键盘快捷键设置中查找其他 `Ctrl+Alt+Z` 绑定。
- 若存在旧 screen-scene 绑定，只有确实希望 TouchFish 禁用这个精确旧绑定时才确认迁移；未经明确确认不会修改。
- 确认 TouchFish 仍在托盘中。关闭设置不会退出，但选择“退出”会停止程序。

## 找不到或无法移动外部程序

点击“捕获当前窗口”，在 3-2-1 倒计时期间切换到目标程序，保存后重试。程序启动较慢时可增加等待时间。若多个可见窗口来自同一可执行文件，请关闭无关窗口后重新捕获。

Ubuntu 可用 `wmctrl -lx` 检查窗口管理器是否暴露目标。Windows 上请让 TouchFish 与目标程序使用相同用户/权限级别；非管理员进程可能无法控制管理员窗口。

## 屏幕分配不对

连接、断开或变更屏幕后，请从托盘退出 TouchFish 并重新启动，再从托盘打开设置，让渲染器读取当前 ID。只重新打开已经隐藏的设置窗口不会刷新初始化时的列表。双屏时检查系统主屏设置及“交换屏幕分配”；三个及以上屏幕选择两个不同的当前 ID。重新插拔硬件可能改变 ID，从而触发回退规则。

## 网页登录或页面行为异常

只接受 HTTP(S) 页面。下载、权限请求和应用内弹窗会被主动拦截。点击“清除网页和登录数据”，重新登录后再试。请求新窗口的链接只有 HTTPS 会交给默认浏览器。

## 开机启动无效

在设置页或托盘关闭再开启“开机启动”。Ubuntu 文件位于 `$XDG_CONFIG_HOME/autostart/touchfish.desktop` 或 `~/.config/autostart/touchfish.desktop`，检查当前用户是否可读。Windows 使用当前用户登录项，可在任务管理器“启动应用”中检查。

## 恢复损坏配置

从托盘退出，再按[重置与恢复](CONFIGURATION.zh-CN.md#重置与恢复)操作。无效配置会自动改名为带时间戳的 `.invalid` 文件。分享前检查其中的本地路径等信息。

## 收集诊断信息

要刷新应用内列表，请先重现场景，等待最终通知，再从托盘退出并重新启动 TouchFish，然后从托盘设置打开“诊断”。渲染器只在初始化时加载诊断列表。日志位于 `<用户数据>/logs/touchfish.log`，最多轮转到 `.4`。报告问题时提供应用版本、系统版本、会话类型、屏幕数量、最终场景状态和已清理的相关日志。不要提交 Cookie、密码、令牌、本地配置或网页会话目录。

安装/发布问题还应记录安装包 SHA-256。Windows 双屏结果要注明是否来自发布后要求的真机冒烟测试。
